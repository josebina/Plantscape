## 分阶段推进

| 阶段 | 交付成果 | 完成条件 |
| --- | --- | --- |
| 1. 固化教学要求 | 需求基线、首关范围、推理教学原则 | 明确哪些来自用户、哪些只是设计建议；本轮已记录 |
| 2. 核验植物与证据 | 十种植物资料卡、关键关系来源、生态条件依据 | 九种已读取来源，仍需交叉核验；杨梅、接受名和当地生态条件待补证；部分官方来源受阻，已提供本地交接 |
| 3. 设计可玩的任务 | 空间图、分镜、证据操作、反馈与评分草案 | 任务关联明确、不存在无解配置、阅读及操作预算合理；本轮形成草案，需用已核验资料修订 |
| 4. 确定视觉与素材 | 场景参考、模型特征清单、移动端界面方案、授权登记 | 识别特征清晰，风格一致，来源和使用权清楚；先做参考与无代码分镜 |
| 5. 汇总制作准备 | 首关设计定稿、素材缺口、实现顺序和验收要求 | 关键教学与视觉问题解决；用户确认前期准备就绪后进入代码制作 |
| 6. 分批实现与验证 | 先一个完整推理闭环，再三种植物，再十种与教师／成绩功能 | 逐批检查教学、画面、移动端操作和性能；最终验证100人并发 |

上述阶段用于控制质量，不意味着每一份可逆文档修改都要请求批准。能够独立完成的准备工作持续推进；涉及游戏代码制作时遵守用户要求，先完成讨论与准备。

## 仓库记录方式

- 已确认信息及时保存；尚待核验的事实不混入正式评分资料。
- 文档以可审阅的提交／分支同步到 GitHub，发布与合并状态分别报告。
- 素材授权、植物来源、题目版本与未来评分版本一同记录。
- 不将凭据、学生个人信息或真实成绩写入仓库。
