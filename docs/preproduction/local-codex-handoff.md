# 本地 Codex 交接包

## 任务与授权范围

继续「植镜」前期准备，核验植物、整理素材、细化教学谜题与视觉设计，并将成果提交回 `josebina/Plantscape`。用户明确要求准备就绪后才开始游戏代码制作；当前不编写游戏、服务器或生产题库代码。

课程与用户决策以 [decisions.md](decisions.md) 为准。十种植物、稳定编号、关系任务与证据要求见 [plant-evidence-cards.md](plant-evidence-cards.md)。本轮实际已查事实见 [source-findings-2026-10-11.md](source-findings-2026-10-11.md)，不能把前期提纲当成全部已审核的植物资料。

## 获取与回传

远端设计分支：`docs/preproduction-foundation`。`main` 尚未合并这些文档。

本地没有项目时：

```bash
git clone --branch docs/preproduction-foundation https://github.com/josebina/Plantscape.git
cd Plantscape
```

已有项目时先查看 `git status` 并保留自己的改动；在工作区允许切换后执行：

```bash
git fetch origin
git switch docs/preproduction-foundation
git pull --ff-only
```

已有同名本地分支并存在分歧时先检查，不能强制重置或强推。离线压缩包仅提供文档快照；正式回传仍应基于 Git 仓库的最新分支，避免覆盖更新。

本地成果检查后，显式添加修改的资料／设计文件、提交并推送此分支。若同时有其他协作者更新，先读取差异并保留两方工作。未经用户要求不合并 `main`、不发布游戏、不采购素材。

## 接手后的五批任务

### 批次1：确认十种植物身份

核对候选学名、接受名与异名，记录采用来源的分类处理；澄清石楠与红叶石楠、酸橙的柑橘处理、栀子与水栀子、园艺类型和裸子植物结构术语。

交付：更新植物身份表，并逐条标记依据。分类名称存在不同处理时如实记录，保留稳定编号P01—P10，不把一种处理写成其他处理错误。

### 批次2：补全植物与关系证据

优先补：P01杨梅资料；P07种托／种子术语；P08身份范围；P10竹种鉴别与地下茎；S03、S06内部不一致之处；所有物种的地区敏感生态断言。

交付：具体断言、来源、章节或页面、适用地区／季节／阶段、支持与限制。将来源支持与教师审核分别标记。没有可靠依据时保留未知，特别是精确生态阈值。

### 批次3：取得并核验素材

从 [asset-candidates.csv](asset-candidates.csv) 的22个候选开始，另补杨梅、酸橙和罗汉松关键结构。

回到来源页取得当时有效的图片链接；不要把临时签名URL、访问密钥或令牌写进仓库。对象定位不保证可直接下载。每张图核对身份、品种、阶段、特征可见性、许可和署名。

清单已去除相同对象的重复记录，并排除扶芳藤页面两张文件名与页面物种有冲突的图片。部分保留候选明确展示园艺类型，只可在确认课程对象与用途后使用，不能直接当作原种统一外观。

来源页显示许可只是第一步，需实际阅读条款。照片授权不等于第三方模型授权。不得把未知、NC或ND资源默认作为可任意修改的游戏素材。

交付：更新资产登记；已授权小图或参考资料按许可放入 `docs/preproduction/assets/` 并保留署名。较大原始资产先列存储需求，不直接把大二进制文件堆进Git。未经下载的条目仍标记候选。

### 批次4：细化任务与视觉

用核验结果修订 [trait-reasoning-map.md](trait-reasoning-map.md)、[lesson-01-puzzles.md](lesson-01-puzzles.md) 与 [lesson-01-storyboard.md](lesson-01-storyboard.md)。制作立体校园庭院、植物观察界面、证据托盘和最终配置界面的参考／静态分镜，先保证手机上特征清晰，再统一材质、光影和色彩。

生成概念图只能作为风格参考，不作为植物事实依据；不能把生成的叶形、花果结构直接投入识别考核。

交付：合理布局例、任务反馈、足够证据与替代解、静态视觉方案、阅读与操作预算。区分估算和实际演练记录，不把计划写成通过验证。

### 批次5：汇总准备状态并回传

列出已经解决／仍待教师决定／仍缺素材的内容。不要自行决定平时成绩权重、学生身份方式或学校平台接入。

检查文档链接、来源与资产关联、十种植物编号、授权登记、相互矛盾的状态说明和意外文件。提交并推送最新设计文档，报告分支、提交号、变更和实际验证结果。等待用户确认准备就绪再进入游戏代码。

## 可直接复制给本地 Codex 的任务

> 请接手 josebina/Plantscape 的 docs/preproduction-foundation 分支，继续「植镜」前期准备。先读取 docs/preproduction/README.md、decisions.md、local-codex-handoff.md、source-findings-2026-10-11.md 和 plant-evidence-cards.md。按交接文件的五批任务执行：确认十种植物身份；补全可靠的形态、功能、生态与景观关系证据，重点补杨梅、酸橙身份及长沙适用条件；核验并收集有授权的素材；细化关联谜题与移动端静态视觉分镜；检查后提交、推送回同一设计分支。继续已完成工作，保留用户改动，不强推，不把未查资料称为核验，不关闭TLS验证，不写入临时签名或凭据。游戏服务于本科《风景园林植物》，长沙校园，手机／平板，独立10—20分钟，十种植物为杨梅、木犀、紫荆、棕榈、扶芳藤、石楠、罗汉松、酸橙、栀子花、孝顺竹。核心是形态—功能—分类—生态—景观的证据推理，不能做成独立知识点题库。用户要求前期准备就绪后再开始游戏代码；本次只做研究、素材和设计，完成后报告成果与待定问题。
